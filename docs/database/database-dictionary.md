# Database dictionary

Status: Milestone 5 Slice 1 Evidence metadata foundation
Authority: `backend/prisma/schema.prisma` plus the eleven ordered directories in
`backend/prisma/migrations/`

This dictionary describes the PostgreSQL schema used by the active backend. It
was reconciled with the Prisma schema, migration SQL, active repositories and
services. Prisma relation fields are not physical columns and therefore do not
appear below.

Conventions:

- `NN` means `NOT NULL`; `NULL` means nullable.
- `PK` means primary key. Prisma's `uuid()` values are generated by the Prisma
  client; the database columns intentionally have no UUID default.
- `now` means PostgreSQL `CURRENT_TIMESTAMP`. `updatedAt` fields are maintained
  by Prisma and have no database default.
- `global` means a row is not owned by one tenant. `tenant` means the row has a
  direct `tenant_id`; join tables without one inherit scope through their
  parents.
- `authoritative` means active application state. `compatibility` is retained
  for backward compatibility and is not the current workflow authority.

The database prohibits future-effective Policy approval, raw dangerous HTML
elements, Policy self-approval, `RESUBMITTED` approval rows, mutable approval
and review history, duplicate active Control/stable-Policy mappings, Control
archival with active Checkpoints, `ACTIVE` Checkpoints under `ARCHIVED`
Controls, invalid frequency-specific review periods, and cross-tenant actors or
relationships. Concurrent Control archive versus Checkpoint activation
serializes on the parent Control row so `ARCHIVED` + `ACTIVE` cannot commit.
An `INACTIVE` Control may still retain an `ACTIVE` Checkpoint in Slice 1; no
trigger automatically changes child or parent lifecycle.

## Authoritative boundaries

- `backend/prisma/schema.prisma` describes the current Prisma client contract.
- `backend/prisma/migrations/` is the only authoritative history that creates
  the database objects.
- PostgreSQL row-level security is not implemented. Tenant isolation relies on
  authenticated tenant context, repository predicates, composite tenant
  foreign keys, checks and triggers. This is a known production hardening item.
- The active backend has no mutation route or repository method for
  `kpi_goals`. Do not treat that compatibility table as the target authority.
